# 科目二重复类别支持设计

## 目标

科目二允许多个箱子识别为相同卡通类别，也允许多个目标识别为相同数字类别。同类别箱子与同类别目标可以任意互配；每个类别的箱子数量与目标数量相等。系统必须在不生成实例编号的前提下完成扫描、校验、规划、ART 同步和失败重试。

## 原有问题

当前 `subject2_binding_struct bindings[SUBJECT2_CLASS_COUNT]` 每个类别只能保存一个 `box_cell` 和一个 `target_cell`：

- 第二个同类识别结果会被 `subject2_bind_box()` 或 `subject2_bind_target()` 拒绝。
- 集合校验只能判断某类别是否同时存在箱子和目标，不能比较重复数量。
- 推箱选择每个类别只尝试一个固定箱子和一个固定目标。
- `retry_active_only` 只记录类别，重复类别下无法确定要重试的具体箱子和目标。

因此不能通过单纯放宽重复检查修复，必须把对象数组改为类别和位置的事实来源。

## 数据模型

`box_objects[MAX_BOXES]` 和 `target_objects[MAX_BOXES]` 保存当前仍存在的每个对象：

```c
cell
class_id
recognized
tried_observation_mask
```

每个对象独立保存类别，允许多个对象具有相同 `class_id`。`bindings[class_id]` 不再作为运行时事实来源，并从科目二扫描、校验、规划和 ART 对象协调接口中移除。

当前推箱任务单独保存：

```c
active_class
active_box_cell
active_target_cell
active_box_valid
```

`active_target_cell` 在重试期间必须固定。`active_box_valid` 表示活动箱是否还能唯一跟踪；无法唯一跟踪时不猜实例，而是从同类别箱子中重新选择可行对象。

## 扫描与分类

识别成功后直接写入当前对象：

```c
objects[current_index].class_id = confirmed_class;
objects[current_index].recognized = 1;
```

同批对象出现重复类别是合法结果，不触发观察位回退、重复冲突或覆盖旧对象。现有连续同类帧、置信度阈值、观察位切换和分类超时规则保持不变。

## 类别数量校验

全部对象识别完成后，分别统计每个类别的箱子数和目标数：

```text
box_class_count[class] == target_class_count[class]
```

所有类别数量相等且至少存在一个对象时校验成功。

若数量不一致，只把所有“数量异常类别”涉及的箱子和目标标记为未识别并重新扫描；数量一致类别的识别结果保持不变。继续复用现有校验重试上限，超过上限后停车报分类错误，不能猜测类别。

## 动态配对规划

每次选择推箱任务时遍历所有已识别箱子与目标：

1. 只考虑 `box.class_id == target.class_id` 的组合。
2. 对每个组合调用现有 `solve_bound_box_path(snapshot, box.cell, target.cell, result)`。
3. 选择动作数最少的可行组合。
4. 保存该组合的 `active_class/active_box_cell/active_target_cell` 并启动 executor。

同类别对象可以任意互配，因此不生成 `8-A/8-B` 等临时实例身份。唯一类别地图自然退化为当前一对一行为。

## ART 对象协调

OpenART #1 的稳定地图继续作为几何和完成状态权威，但不提供箱子类别。

### 途经目标遮挡

上位机可能在箱子经过非最终目标时用目标图层完全遮住箱子，OpenART 因而只能输出 `T`。MCU 使用内部字符 `*` 表示“箱子站在目标上”，该字符不属于 OpenART UART 协议。

只有以下条件全部成立时才把 ART 的 `T` 规范化为 `*`：

```text
最近完成动作是 U/D/L/R
ART 地图恰好少一个 B，T 数量未减少
规划动作重放得到的箱子格位于 C 前方一格
该格在 ART 地图中为 T
该格不是当前任务最终目标
```

`*` 在统计和求解中同时计作一个箱子和一个目标。箱子离开该格后恢复普通 `B/T`；真正到达最终目标时仍必须等待上位机让对应 `B/T` 同时消失。

### 目标

目标不会移动：

- 新图中原格仍存在的目标继承原类别。
- 原格消失的目标从对象列表移除。
- 出现无法对应到旧目标格的新目标时视为地图矛盾，不发布部分同步结果。

### 箱子

协调新箱子格时按以下顺序处理：

1. 原格仍存在的箱子继承原类别。
2. 统计协调后剩余目标的每类数量，得到剩余箱子必须满足的类别数量。
3. 对未匹配箱子计算每类缺额。
4. 只有一个类别存在缺额时，把未匹配箱子赋为该类别。
5. 多个类别同时存在缺额且位置无法唯一判断时，只将未匹配箱子标记为未识别，进入 ART2 局部箱子扫描。

完成类别由剩余目标的类别数量变化确定，不要求识别“究竟是哪一个同类实例”完成。同类别对象可互换，因此同类内部的位置交换不构成错误。

### 完成与返航

- `B/T` 等量减少一个或多个时更新对象数组并重新规划。
- `B=0,T=0` 时进入现有返航流程。
- 结构非法或局部扫描后类别数量仍无法一致时才停车。

## 推箱失败重试

任务未完成时继续尝试原 `active_target_cell`：

```text
active_box_cell -> active_target_cell
```

活动箱能够唯一跟踪时继续使用更新后的 `active_box_cell`。若活动箱无法唯一跟踪但剩余箱子类别仍可由目标配额确定，则保留目标格，从同类别箱子中重新选择最短可行组合；只有多个类别缺额无法恢复时才局部重识别未匹配箱子。

## 保持不变

- 不修改 OpenART #1、OpenART #2 UART 文本协议。
- 不修改模型标签、置信度阈值和连续稳定帧数量。
- 不修改 BFS、executor、PID、20cm 格距、发车和返航算法。
- 不给重复对象生成顺序相关的持久实例编号。
- 总箱子数和目标数继续受 `MAX_BOXES` 限制。

## 验证

- 两个同类箱子和两个同类目标全部识别后校验成功。
- 第二个同类识别结果不会触发回退或覆盖第一个对象。
- 同类别四种箱子目标组合中选择动作数最少的可行路径。
- 唯一类别地图的选择结果与当前行为一致。
- 某个同类目标消失后，同类别剩余数量正确减少，不要求区分同类实例。
- 同类箱子交换位置不触发 `E:Track`。
- 多类别箱子同时发生无法唯一解释的位置变化时只局部重扫未匹配箱子。
- 推箱未完成时重试原具体目标，不会切换到另一个同类目标。
- 全部完成后正常返航。
- 全量 C 主机测试和 Keil 编译通过，Keil 为 `0 Error(s), 0 Warning(s)`。
