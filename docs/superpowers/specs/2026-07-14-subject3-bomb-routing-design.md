# 科目三按需炸墙与分类推箱设计

## 1. 目标与范围

科目三在科目二“观察、分类、绑定、指定推箱”的基础上增加炸弹。第一版以完整、稳定跑通为优先，只在当前任务无解时使用炸弹，不为了缩短一段可达路径主动炸墙，也不做炸弹、箱子和所有墙状态的联合全局最优搜索。

已确认的比赛规则：

- `X` 是可推动炸弹，`#` 是固定墙体。
- 把炸弹推入内部墙格时触发爆炸。
- 爆炸触发后，该炸弹自身从地图中消失。
- 爆炸中心是炸弹被推入的墙格，范围为以该格为中心的 `3x3`。
- 爆炸只删除范围内的内部墙体，不删除箱子、目标点或小车。
- 最外围一圈墙不能炸毁，也不能作为爆炸目标。

本设计不改变科目一、科目二的分类模型、箱子目标绑定规则、车箱二维准备位、路径 PID 或返航流程。

## 2. 总体策略

科目三采用“两次可达性检查 + 按需单次炸墙”：

```text
发车并取得稳定地图
-> 检查所有箱子和目标是否具有可达观察位
   -> 不满足：选择一次爆炸，推弹并等待 ART 确认，然后重新检查
-> 复用科目二完成全部分类并建立箱子到目标绑定
-> 检查每个已绑定推箱任务是否可解
   -> 不满足：选择一次爆炸，推弹并等待 ART 确认，然后重新检查
-> 复用现有推箱执行流程完成全部箱子
-> 复用现有返航流程回到发车区
```

每次只规划一颗炸弹和一个爆炸中心。地图发生爆炸变化后，之前对后续炸弹和路径的预测全部作废，必须使用最新稳定 ART 地图重新分析。

## 3. 状态机

科目三作为科目一、科目二之上的比赛阶段，不把炸墙逻辑塞进 executor：

```text
S3_WAIT_MAP
-> S3_CHECK_OBSERVE
-> S3_SELECT_BLAST
-> S3_PLAN_BOMB
-> S3_EXECUTE_BOMB
-> S3_CONFIRM_BLAST
-> S3_CHECK_OBSERVE
-> S3_CLASSIFY
-> S3_CHECK_PUSH
-> S3_SELECT_BLAST
-> S3_PLAN_BOMB
-> S3_EXECUTE_BOMB
-> S3_CONFIRM_BLAST
-> S3_CHECK_PUSH
-> S3_EXECUTE_PUSH
-> S3_RETURN
-> S3_DONE
```

`S3_SELECT_BLAST` 只在当前检查确实存在无解任务时进入。如果地图中没有炸弹、所有炸点均不可执行或爆炸后仍不能解锁任务，则停车进入科目三规划错误，不盲目移动。

## 4. 观察可达性检查

分类前，对每个 `B` 和 `T` 复用科目二现有观察位生成规则：

- 对象四邻域中的合法空地均可作为候选观察位。
- `#`、`B`、`X` 和其他不可通行元素不能作为观察位。
- 使用普通小车导航 BFS 判断至少一个候选观察位是否可达。
- 每个箱子和目标至少有一个可达观察位，才允许进入分类阶段。

若某个对象没有可达观察位，记录该对象作为本轮炸墙需要解锁的任务。炸墙后不沿用旧观察路径，重新扫描最新地图并重新生成候选观察位。

## 5. 分类后推箱检查

科目二完成全部识别并建立唯一绑定后，科目三暂停正式推箱，逐个检查已绑定的 `箱子 -> 目标` 任务。

- 检查使用当前单箱求解规则和当前真实箱子布局。
- 只要求每个已绑定任务存在可执行解，不要求一次得到全部任务的全局最优顺序。
- 若全部任务可解，交还现有科目二/科目一推箱执行链。
- 若存在无解任务，只针对当前无解绑定选择爆炸点。

爆炸只删除墙，已识别的箱子类别和目标类别不改变，因此炸墙后可保留绑定结果；但箱子格、目标格、小车格和执行路径必须从最新 ART 地图重新建立。

## 6. 爆炸候选与模拟

候选爆炸中心必须同时满足：

- 当前格是非外圈 `#`。
- 存在一颗炸弹能够通过合法推动路径被推入该墙格。
- 最后一次推动时，小车能到达炸弹背后的支撑格。
- 规划过程中不推动普通箱子，不穿过其他炸弹或墙。

对候选墙 `(row, col)` 做纯逻辑模拟：

```text
for r in row-1 .. row+1
    for c in col-1 .. col+1
        如果 (r,c) 不是地图最外围并且是 '#'
            临时改为 '.'
```

`B`、`T`、`C` 和其他 `X` 不受模拟爆炸影响。模拟地图只用于评分，不得直接发布为真实地图或更新执行基线。

## 7. 炸点选择

第一版使用稳定的字典序评分，不合成难以调试的浮点权重：

1. 爆炸后当前无解任务必须变成有解，否则淘汰。
2. 优先一次解锁更多不可达观察任务或无解绑定任务。
3. 优先炸弹推动次数更少的方案。
4. 再比较小车普通移动步数。
5. 总步数相同时，优先转折更少的方案。
6. 仍相同时按炸弹行列、墙行列固定排序，保证同一地图结果可复现。

第一版不因“能缩短已有可行路径”使用炸弹。该优化可在完整流程稳定后作为独立版本增加。

## 8. 炸弹路径求解

炸弹 BFS 状态为：

```text
state = player_cell + bomb_cell
```

地图处理：

- 普通移动时，`#`、所有 `B` 和其他 `X` 不可进入。
- 当前选中炸弹与普通箱子一样只能被推动，不能拉动。
- 炸弹不能被推入普通墙；唯一例外是最后一步推入选定爆炸中心。
- 外圈墙永远不能作为最后一步目标。

终止条件不是“炸弹已经站在目标格”，而是当前状态存在一次合法推动，可以把选中炸弹推入选定墙格。输出路径包含这次最终推动。

炸弹路径是独立任务。它可以复用 waypoint 和底盘位置环，但不能复用黄色箱子中心的 `OBSERVE_REQ` 校正，也不能进入普通 `B/T` 减少确认。第一版在炸弹推链开始前只请求小车中心并校正 pose，随后按格点路径完成推动。

## 9. 爆炸确认

最终推动完成后立即停车，等待连续稳定的新 ART 地图。确认条件全部满足才接受爆炸：

- 地图中 `C` 唯一且帧完整。
- `X` 数量比爆炸前减少 1。
- 爆炸前位于预期 `3x3` 内的所有内部墙，在新图中均不再是 `#`。
- 外圈墙保持不变。
- `B` 和 `T` 数量没有变化。

确认成功后：

- 保存最新 ART 地图。
- 使用配套小车中心重新建立当前 pose offset。
- 清除旧炸弹路径和旧任务可达性结果。
- 回到 `S3_CHECK_OBSERVE` 或 `S3_CHECK_PUSH`。

确认超时、`X` 未减少、墙未按预期消失或 `B/T` 异常变化时，立即停车报错，不使用 MCU 模拟地图继续运行。

## 10. 模块边界

- OpenART #1：继续输出 `# . B T C X` 和小车中心，不做炸点决策。
- `subject3`：负责科目三状态机、两次可达性检查、调用分类/推箱阶段和爆炸确认。
- 科目三纯逻辑：负责 `3x3` 爆炸模拟、候选评分和确定性选择，优先放入可主机测试的独立逻辑模块。
- `solver`：增加单炸弹到单墙的 BFS，不改变现有箱子 BFS 的 `X` 障碍语义。
- `subject2`：继续负责观察、分类和绑定；增加“绑定完成后交还上层检查”的明确边界。
- `executor`：只执行给定 waypoint；炸弹任务不启用黄色箱子中心准备和普通推箱段末 `B/T` 同步。
- `competition_flow`：增加科目三调试模式和完整比赛中的科目三阶段。

## 11. 错误策略

科目三不做无条件降级继续：

- 无可达观察位且无有效炸点：规划错误。
- 已绑定推箱任务无解且无有效炸点：规划错误。
- 炸弹路径无解：炸弹规划错误。
- 炸弹执行超时或 executor 报错：运动错误。
- 爆炸地图确认失败：同步错误。
- 所有错误均先停车，保留最新真实 ART 地图和失败阶段供屏幕/VOFA 调试。

## 12. 验证范围

纯逻辑测试至少覆盖：

- `3x3` 中内部墙被删除，外圈墙保持不变。
- 爆炸不删除 `B/T/C/X`。
- 候选墙不可炸、炸弹无法到达、支撑格不可达时淘汰。
- 多个候选都有效时按固定评分得到可复现结果。
- 观察位从不可达到可达。
- 已绑定推箱任务从无解到有解。

炸弹 BFS 测试至少覆盖：

- 直线推动、绕行后推动、多个炸弹、普通箱子阻挡。
- 不能推入非目标墙和外圈墙。
- 最后一步推入目标墙后路径结束。

流程测试至少覆盖：

- 无需炸墙时直接进入分类，不浪费炸弹。
- 分类前因观察位不可达执行一次炸墙。
- 分类后因指定绑定无解执行一次炸墙。
- 爆炸成功后使用最新地图重算。
- `X` 未减少、墙未消失、`B/T` 变化时均停车。
- 多次炸墙时每次只规划一次，不能沿用爆炸前的后续路径。

## 13. 第一版不做

- 不为了纯路径缩短主动使用炸弹。
- 不做多炸弹和多箱子的联合全局最优搜索。
- 不识别炸弹精确中心，不做推弹过程中的视觉闭环。
- 不让 OpenART 决定炸点或维护虚拟地图。
- 不在未收到爆炸后稳定 ART 地图时继续执行。
