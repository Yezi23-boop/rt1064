# 科目二车头朝向与观察流程设计

## 1. 目的

科目二需要由车载 OpenART #2 识别箱子图案和目标数字。OpenART #2 安装在车头，只有车头正对被观察对象时才能可靠识别。

当前科目二选择对象相邻的可达观察格并导航到位后，先用小车精确中心驱动实车回到观察格中心，再原地转向对象。箱子和目标使用同一流程，箱子精确中心暂不参与分类观察。

本文档覆盖 `2026-07-12-subject2-classified-sokoban-design.md` 中与观察位置、中心校正和分类顺序有关的内容；其余类别绑定、指定配对求解、地图确认和返航设计保持不变。

## 2. 系统分工

```text
OpenART #1（UART1）
  - 识别 16x12 字符地图
  - 输出小车精确中心
  - 保留箱子精确中心识别能力，但本版扫描流程不使用

OpenART #2（UART4）
  - BOX 模式识别箱子图案
  - TARGET 模式识别目标数字

RT1064
  - 选择观察对象和观察格
  - 导航、原地转向和小车中心校正
  - 请求分类并建立类别绑定
  - 指定配对求解、路径执行、地图确认和返航
```

## 3. 坐标与车头约定

- 开机时车头朝地图上方，控制层 `yaw=0deg`。
- 控制层 `+yaw` 为逆时针。
- 麦轮底盘允许保持任意 yaw 按世界坐标平移。

四个观察方向对应的绝对目标 yaw：

| 被观察对象相对小车的位置 | 小车所在观察格 | 目标 yaw |
|---|---|---:|
| 上方 | 对象下方 | `0deg` |
| 右侧 | 对象左侧 | `-90deg`（控制层归一化为 `270deg`） |
| 下方 | 对象上方 | `180deg` |
| 左侧 | 对象右侧 | `+90deg` |

识别完成后不恢复 `yaw=0deg`。小车保持当前朝向平移到下一个观察格，到达后再转向新的对象。

## 4. 总体流程

```text
发车并等待科目二地图
-> 扫描全部箱子图案
-> 扫描全部目标数字
-> 校验并建立同类别绑定
-> 逐个执行指定箱子到指定目标的路径
-> OpenART #1 确认单箱任务结果
-> 所有箱子完成后返航
-> Done
```

### 4.1 发车与有效地图

科目二调试模式下，K3 后直接进入科目二发车流程。只有收到满足以下条件的地图才进入扫描：

- `C=1`
- `B>0`
- `T>0`
- `B==T`
- `C` 位于推箱地图有效区域

发车区画面不能求解、不能判断 Done、不能建立 B/T 基线。

## 5. 观察任务规划

### 5.1 候选观察格

对每个尚未识别的箱子或目标，枚举对象上下左右四个相邻格：

- `#`、`X`、`B` 不能作为观察格或导航通路。
- 观察格必须能由 `solve_navigation_path()` 到达。
- 观察格不能同时与两个同类型对象相邻，避免 ART #2 无法确定正在识别哪个对象。
- 已经失败的对象方向通过 `tried_observation_mask` 排除。
- 在所有合法候选中选择导航动作数最少的观察任务。

观察距离固定为相邻格中心，即对象中心与小车中心的标称距离为 `GRID_SIZE_CM=20cm`。

### 5.2 观察计划数据

观察计划除对象索引、观察格和方向位外，还必须保存目标 yaw。目标 yaw 由“对象格减观察格”的方向唯一计算，不由当前路径最后一个动作推断。

## 6. 统一扫描状态机

箱子和目标统一使用以下主流程：

```text
VPos
-> VCtr
-> VAdj
-> VTurn
-> VWait
```

VCtr 校正 MCU pose；随后始终进入 VAdj，使用现有位置环让实车回到格子中心。每个对象只请求一次中心，不进行第二次中心复核。

### 6.1 VPos：导航到观察格

- 使用现有 `solve_navigation_path()` 和 executor。
- 导航只改变世界坐标位置，保持当前目标 yaw。
- 已经位于观察格时跳过导航，直接进入 `VCtr`。
- 导航失败进入 `E:Move`。
- Step 模式只逐步控制导航 waypoint；到达最终观察格后，转向、中心校正和分类自动连续执行，不再等待 K3。

### 6.2 VCtr/VAdj：小车回到观察格中心

到达观察格后发送一次：

```text
CENTER_REQ
```

OpenART #1 返回 3 个顺序样本：

```text
CENTER_SAMPLE 1,...
CENTER_SAMPLE 2,...
CENTER_SAMPLE 3,...
```

MCU 对 `col_q`、`row_q` 分别取中值，根据当前地图 `C` 格中心计算格内偏移并更新 pose，然后固定调用 `executor_start_position_correction(0,0)` 进入 VAdj。偏差已在 `PATH_ARRIVAL_THRESHOLD_CM` 内时，位置环只完成连续到点确认，不产生多余移动。

VAdj 复用现有位置环和 `EXEC_ART_SYNC_TIMEOUT_MS`。完成后更新当前 pose offset 并进入 VTurn；启动失败、执行器错误或超时均停车并显示 `E:CPos`。VAdj 完成后不再请求第二次中心。

中心只有满足以下条件才可信：

- OpenART #1 字符地图中的 `C` 必须严格等于当前规划观察格。
- 中心坐标必须位于 16x12 地图范围内。
- X/Y 任一轴相对 `C` 格中心的偏差不能超过统一的 `EXEC_ART_CENTER_ABNORMAL_CM=20cm`。
- 中心采样期间地图中的 B/T 对象集合不能变化。

10 秒内收不满 3 帧进入 `E:CTmo`；地图持续不匹配进入 `E:CMap`；中心坐标越界、偏差异常或物理调整失败进入 `E:CPos`。中心链路错误不能通过更换观察方向重试。

### 6.3 VTurn：车头正对对象

进入状态时：

```text
set_motion(0, 0)
set_target_yaw(observation.target_yaw)
```

主循环读取由 20ms 控制反馈相位更新的 `yaw_error`，但稳定判定使用 `time_ms()`，不按 `subject2_tick()` 调用次数计数：

- `abs(yaw_error) <= 1deg` 连续 100ms，判定转向完成。
- 任一时刻超出阈值，连续计时清零。
- 10 秒内未稳定，停车并进入 `E:Yaw`。

转向使用现有 yaw 姿态环、最短角误差和角度归一化，不新增转向 PID。

### 6.4 VWait：ART #2 分类

箱子扫描使用：

```text
VISION_MODE BOX
cartoon_V3.tflite
```

目标扫描使用：

```text
VISION_MODE TARGET
number_V1.tflite
```

分类确认条件：

- `confidence_q >= SUBJECT2_CLASS_CONFIDENCE_Q`，当前为 750。
- 连续 `SUBJECT2_CLASS_STABLE_SAMPLES` 个样本类别一致，当前为 3。
- 单个观察方向最长等待 `SUBJECT2_VIEW_TIMEOUT_MS`，当前为 20 秒。

分类成功后发送匹配请求号的 ACK，记录类别与对象地图格的绑定。超时、类别重复或绑定冲突时，标记当前观察方向失败并重新规划；所有观察方向均失败后进入 `E:Class`。

切换 BOX/TARGET 模式时立即发送一次 `VISION_MODE`。未收到对应 `VISION_READY` 时每 1 秒重发，累计等待 10 秒仍未 READY 则停车并进入 `E:Class`。

每次分类只发送一次带新 `request_id` 的 `VISION_REQ`，请求期间不重复发送，避免 OpenART #2 重置样本序号。20 秒未得到稳定类别时发送 `VISION_CANCEL`，再更换观察方向。

首版继续使用 ART #2 整图分类，依靠相邻观察位置和车头方向隔离当前对象，不增加 ROI。

## 7. 箱子精确中心的范围

本版扫描流程不调用箱子中心观察协议：

```text
OBSERVE_REQ
OBSERVE_SAMPLE
VObs
VChk
```

不再为了识别箱子图案而执行“小车中心与箱子中心对齐”。扫描阶段仍会根据小车中心最多执行一次“回观察格中心”修正，但该动作与箱子中心无关。

OpenART #1 的箱子中心检测、UART 协议和 MCU 接收接口暂时保留，但不由科目二扫描状态机调用。后续单独设计箱子中心如何用于推箱前定位或推箱路径校正，不在本次实现中提前决定。

## 8. 类别绑定与指定求解

扫描完成后必须满足：

- 同一批箱子没有重复类别。
- 同一批目标没有重复类别。
- 箱子类别集合与目标类别集合完全一致。
- 集合不一致时只重扫不匹配对象；重扫后仍不一致则进入 `E:Class`。

对每个有效类别调用：

```c
solve_bound_box_path(box_cell, target_cell, result)
```

求解器只能把指定箱子送到同类别指定目标，不允许改选更近目标。多个未完成任务中优先执行动作数较少的可解任务。

## 9. 推箱执行与地图确认

真实车不接触物理箱子，`U/D/L/R` 表示虚拟推箱动作边界。推箱阶段暂不要求车头朝向运动方向，麦轮继续按世界坐标执行路径。

运动方向发生变化时进入 `PCtr`；同方向普通移动切换到大写推箱不触发校正：

```text
停车
-> 请求3帧小车中心
-> 校正pose
-> 继续执行推箱路径
```

单箱任务结束点进入 `ART Wait`：

- `B/T` 各减少 1：当前类别任务完成。
- `B/T` 数量不变：跟踪活动箱子位置，只重算当前类别。
- 地图变化无法唯一解释：进入 `E:Track`。

确认后通过 `RCtr` 重新校正小车中心，再选择下一项任务。

## 10. 返航

最后一个箱子和目标消失后：

```text
S2Ret
-> 地图 BFS 返回左侧出口格
-> OpenART #1 精确中心校正
-> 返回启动时保存的发车中心
-> Done
```

## 11. 屏幕状态

Execute 页在 ART 车格行右侧显示最近一次连续确认并成功绑定的分类结果：
`R:B4` 表示箱子卡通对应类别 4，`R:T4` 表示目标数字 4。单帧预测和低置信度结果不显示。

| 状态 | 含义 |
|---|---|
| `BScan` | 等待箱子模型 READY |
| `TScan` | 等待数字模型 READY |
| `VPos` | 导航到观察格 |
| `VCtr` | 请求并应用小车精确中心 |
| `VAdj` | 使用位置环回到观察格中心 |
| `VTurn` | 原地转向并等待 yaw 稳定 |
| `VWait` | 等待 ART #2 分类结果 |
| `VRetry` | 当前观察方向失败，重新规划 |
| `Bind` | 校验绑定或选择推箱任务 |
| `S2Push` | 执行指定推箱路径 |
| `PCtr` | 路径方向转折点中心校正 |
| `ART Wait` | 等待地图确认任务结果 |
| `RCtr` | 重规划前小车中心校正 |
| `S2Ret` | 科目二完成并返航 |
| `E:Yaw` | 观察转向超时或无法稳定 |
| `E:CTmo` | 三帧小车中心请求超时 |
| `E:CMap` | 观察格 C 或 B/T 地图持续不匹配 |
| `E:CPos` | 小车中心坐标越界或偏差异常 |
| `E:CPsh` | 推箱前中心校正失败 |
| `E:CRpl` | 重规划中心校正失败 |
| `E:Class` | 分类或类别集合失败 |
| `E:Track` | 箱子身份变化无法唯一判断 |
| `E:Plan` | 指定配对任务无解 |

## 12. 实现边界

本次只修改科目二观察行为：

1. 箱子和目标统一执行 `VCtr -> VAdj -> VTurn`。
2. 每个观察对象都执行一次物理回中心，不做第二次中心复核。
3. 箱子扫描不调用箱子中心联合校正。
4. 保持当前朝向平移到下一个观察格。
5. 保留但不调用箱子中心协议和检测实现。
6. 为 VTurn、VCtr、回中心和 ART #2 READY 增加已经确定的超时行为。

本次不修改：

- 地图 BFS 和指定配对 BFS 算法。
- 轮速 PID、yaw PD、里程计和格距。
- ART #2 分类协议和模型。
- 推箱任务确认、身份追踪和返航逻辑。
- 推箱阶段对箱子精确中心的未来用途。

## 13. 验收标准

### 主机测试

- 四个观察方向分别生成正确目标 yaw。
- 已在观察格时直接请求中心，位置修正完成后再转向。
- 转向连续稳定计时在误差越界时清零，主循环调用频率不能缩短 100ms 要求。
- 转向超时进入 `E:Yaw` 并停车。
- 箱子扫描不发送 `OBSERVE_REQ`，只发送 `CENTER_REQ`。
- 首次中心在 0.5cm 内时仍进入 VAdj，但只进行到点稳定确认。
- 每个观察对象只执行一次回中心，随后校验 yaw，不再次请求中心。
- 中心超时、地图 C 不匹配、数据异常或复核失败均进入 `E:Ctr`。
- BOX/TARGET 模式等待 READY 时每秒重发，10 秒超时进入 `E:Class`。
- 分类 `VISION_REQ` 不重发，20 秒失败后 CANCEL 并更换观察方向。
- 箱子和目标均在位置和 yaw 条件满足后才请求 ART #2 分类。
- 原有分类绑定、扫描重试、指定求解和推箱确认测试保持通过。

### 上板测试

- 从四个方向观察对象时，车头均能正对对象。
- 转向过程中 ART #2 不开始分类。
- 转向前先完成小车中心校正；存在位置偏差时真实回到观察格中心。
- 回中心后确认 yaw，再开始分类，不重复请求小车中心。
- 识别完成后不回正，能保持当前 yaw 平移到下一观察格。
- 箱子扫描过程不再出现 `VObs/VChk`；`VAdj` 仅表示小车回观察格中心。
- UART1 地图与中心、UART4 分类通信保持正常。
