# ART 发车区与科目二观察后 Yaw 校准设计

## 目标

每个科目只在左侧发车区使用一次 OpenART #1 的车头 yaw 建立该科目的 MCU 姿态基准。科目一只建立参考、不旋转；完整模式切换到科目二后，在同一发车点比较两科 yaw，偏差达到阈值才实际回正。科目二全部观察完成、`HYaw` 稳定后额外允许一次保守小角校准；除此之外场内 yaw 只能用于调试显示。

同一车头方向在场地不同位置存在不同的透视、色块离散和亮度偏差，因此观察后校准只接受不超过 `6°` 的偏差，不做场内大角度纠正，也不允许重复触发。

完整模式正常校准两次：科目一发车前一次，科目一返航并切换到科目二后、科目二发车前再一次。科目一或科目二单独调试模式只校准对应科目一次。

## 每科目唯一校准窗口

只有同时满足以下条件才允许校准：

```text
当前处于科目一或科目二的 ART 发车阶段
PLAYER_CENTER_GRID 有效
中心所在 row = 5 或 6
中心所在 col = 0 或 1
发车移动尚未开始
当前科目尚未建立 yaw 基准
```

当前科目的发车移动一旦开始，该科目校准入口永久关闭。返航重新进入发车区不能自动打开入口；只有 `competition_flow` 明确切换到下一科目的发车阶段，才能为新科目重置一次校准权限。

## ART Yaw 识别

小车由绿色车身和青色车头组成。精确中心 ROI 内将车身像素唯一划分为绿色或青色，提取靠近两色中心中面的绿青分界点，对分界点做总最小二乘直线拟合；分界线法线为车身轴，青色所在一侧为车头正方向。

地图 yaw 约定：

```text
下 = 0°
右 = 90°
上 = 180°
左 = 270°
```

分界点不足、长短轴比不满足门限或绿青距离异常时，本帧 yaw 无效，但不能影响小车中心、地图发布或发车位置计算。

运行模式只在发车校准请求活跃时计算精确 yaw；调试模式可以持续计算和显示，但调试结果不具备 MCU 修正权限。

## UART 与样本

扩展发车阶段使用的中心样本，不新增独立请求命令：

```text
MCU -> CENTER_REQ
ART -> CENTER_SAMPLE index,col_q,row_q,yaw_q,yaw_valid
```

- `yaw_q` 单位为 `0.01°`，范围 `0..35999`。
- `yaw_valid=0` 时 `yaw_q=0`，中心样本仍可用于原有位置流程。
- MCU 收集5帧 yaw，使用圆周 medoid 排除与参考相差超过 `5°` 的帧，再做 `sin/cos` 圆周平均。
- 至少需要 `4/5` 帧有效，才能建立当前科目的发车 yaw 基准。
- OpenART 与 MCU 固件需要同步升级；协议升级前 yaw 仍只是 OpenART 本地调试值。

## 发车区基准

发车区物理摆放方向已知。当前约定车头朝上，即：

```text
expected_launch_yaw_deg = 180°
```

科目一或单科调试模式得到稳定样本后记录：

```text
art_yaw_bias_deg = shortest_angle_error(expected_launch_yaw_deg,
                                        measured_art_yaw_deg)
reference_valid = 1
```

例如实际为 `180°`，ART 稳定输出 `177.46°`：

```text
art_yaw_bias_deg = +2.54°
```

首科建立基准不命令小车旋转，只记录 ART 固定偏差并原子锁定当前 IMU yaw、重建局部 pose 零点。随后当前科目的执行和返航全部依靠该科目的 IMU 基准及现有姿态闭环。

完整模式科目二回到同一发车点后，使用首科偏差修正当前 ART yaw，再计算到 `180°` 的最短角误差：

- 偏差不超过 `5°`：不转，直接重建科目二 IMU/pose 基准。
- 偏差在 `5°~10°`：按最短角度实际回正。
- 偏差超过 `10°`：重新采集一批；两批相差不超过 `3°` 才回正，否则放弃视觉转向。
- 科目二中心与首科参考中心任一轴相差超过 `ART_RETURN_HOME_TOLERANCE_Q` 时不比较，避免把位置相关视觉误差当成漂移。

回正沿用科目二现有 `0.5°` 到点、`100ms` 稳定和 `10s` 超时。只有已经开始回正后超时才停车并显示 `E:Yaw`；yaw 无效、首批超过 `3000ms`、复采失败或位置不匹配都只降级为锁定当前 IMU 后继续发车。

若发车区 yaw 样本无效或超时，当前科目继续使用现有 IMU 启动基准，不盲目旋转。没有有效发车 bias 时，科目二观察后校准直接跳过。

## 科目二观察后校准

科目二全部箱子和目标分类绑定成功后，先按原流程执行 `HYaw`。连续稳定 `100ms` 后停车发送一次 `CENTER_REQ`，使用发车 bias 修正5帧圆周平均 yaw：

- 偏差不超过 `2°`：不旋转，只锁定当前 IMU yaw 并重建 pose 零点。
- 偏差在 `2°~6°`：按最短角实际回正，达到 `0.5°` 并稳定 `100ms` 后重建基准。
- 偏差超过 `6°`、发车 bias 无效、配套中心地图非法、有效 yaw 少于 `4/5` 或等待超过 `3000ms`：不修正，继续推箱。
- 已经开始转向但 `10s` 未完成：停车并显示 `E:Yaw`。

该入口每轮科目二只消费一次；单个观察点、推箱重规划、任务完成和返航都不能重新打开。

## 每科目发车后的硬门控

以下事件全部禁止 ART yaw 修正：

- 发车出区移动。
- 首次真实地图加载和科目一求解。
- 科目一推箱、重规划和返航。
- 科目一返航完成但尚未进入科目二发车阶段。
- 科目二单个观察、主动旋转和 `HYaw` 回正过程；仅 `HYaw` 稳定完成后的单次入口例外。
- 科目二推箱、完成确认和返航。
- 当前科目返航重新进入发车区。

`HYaw` 仍先使用当前科目发车时保存的 IMU 基准回正，稳定后才请求当前位置的 ART yaw。科目一返航到发车区后，必须先完成科目切换，再以“科目二发车校准”身份重新采样；科目二最终返航只允许显示或记录 ART yaw，不再修正。

## 模块边界

- `openmv/main_see.py`：生成原始 yaw 和扩展后的 `CENTER_SAMPLE`，不决定 MCU 是否校准。
- `openart_uart` / `art_observation`：解析并圆周过滤5帧 yaw，不修改姿态。
- `competition_flow` / `menu`：新比赛清除整轮参考；切换科目只开启科目二的一次校准权限，普通返航不得重置参考。
- `art_replan`：每个科目只在发车阶段和发车区窗口内建立一次基准；当前科目发车开始后锁死入口。
- `subject2`：在 `HYaw` 稳定后启动一次保守 ART yaw 校准，其余状态不得消费 yaw。
- `drive_control` / `drive_pose`：原子启动相对 yaw 回正，或锁定当前 yaw 并重建 pose 零点。

业务调用点只有发车流程和科目二观察结束后的单次入口，不增加其他场内校准点。

## 保持不变

- 不修改地图字符、`OBSERVE_SAMPLE`、ART2 协议、BFS、PID和20cm格距。
- 不在运动中持续用视觉 yaw 覆盖 IMU。
- 不因 yaw 失败阻塞小车中心、地图、求解或发车位置流程。
- 不在科目一结束状态、科目二推箱过程或返航前增加其他校准。

## 验证

- 科目一和科目二各自在发车区 `row=5/6、col=0/1` 收集5帧并各建立一次基准。
- 样本为 `176~178°` 且物理方向已知为 `180°` 时，只记录偏差，不实际旋转。
- 科目二同点观测相对首科偏差 `7°` 时实际回正；偏差不超过 `5°` 时不增加转向动作。
- 科目二偏差超过 `10°` 时必须通过第二批 `3°` 一致性检查。
- 当前科目发车移动开始后，任何 `CENTER_SAMPLE` yaw 都不能再次修改该科目基准。
- 科目一返航本身不触发校准；切换到科目二发车阶段后允许科目二校准一次。
- 科目二 `HYaw` 后只校准一次；推箱、重规划、返航前和返航终点均不得再次触发。
- 观察后偏差恰好 `2°` 不转，恰好 `6°` 允许回正，超过 `6°` 直接跳过。
- 某科目发车区样本不足或无效时继续使用 IMU，也不禁止下一科目独立尝试。
- 圆周样本 `359/0/1/2/20°` 不会平均成 `180°`，异常 `20°` 被拒绝。
- OpenART Python 测试、相关 C 主机测试、`git diff --check` 和 Keil 编译全部通过后，才视为协议与 MCU 实现完成。
