# 科目二分类推箱设计

## 1. 目标与范围

科目二从科目一返航后的左侧发车区再次出发。OpenART #1 继续识别 16x12 地图和小车精确中心，OpenART #2 识别箱子侧面的卡通类别和随机目标上的数字。MCU 先识别完全部箱子和目标，建立唯一的箱子到目标绑定，再逐个执行指定配对推箱。

本设计覆盖普通分类模式和目标随机分布的升级模式，不依赖目标并排。暂不包含炸弹和科目三策略。

## 2. 运行模式

调试阶段使用编译期模式区分运行范围：

```c
COMPETITION_MODE_SUBJECT1_DEBUG
COMPETITION_MODE_SUBJECT2_DEBUG
COMPETITION_MODE_FULL
```

- `SUBJECT1_DEBUG`：只运行科目一，完成返航后结束。
- `SUBJECT2_DEBUG`：从发车区直接运行科目二，不要求先完成科目一。
- `FULL`：第一次按 K3 后完成科目一；返航后等待上位机自动切换关卡，MCU 不再等待第二次 K3，自动再次发车并完成科目二，最终返航结束。

科目一返航后进入独立的科目切换状态。该状态清除科目一地图基线、求解结果和科目二分类表，但保留本轮发车区 `home` 精确中心。收到切关后的新 OpenART #1 帧后复用现有发车流程，再等待真正的科目二地图。

## 3. 模块边界

### 3.1 MCU

- `art_replan.c`：保留科目一地图同步、精确中心、推箱确认和返航职责，只增加科目完成及再次发车衔接。
- `subject2.c/.h`：科目二扫描状态机、观察任务选择、类别绑定、绑定校验和箱子身份追踪。
- `vision_uart.c/.h`：OpenART #2 UART 协议、请求序号和分类样本队列。
- `solver.c/.h`：增加指定箱子到指定目标的单任务求解接口；现有科目一任意配对接口保持不变。
- `drive_config.h`：增加运行模式和必要分类参数。

### 3.2 OpenART

- OpenART #1：现有地图与请求式精确中心程序保持不变。
- OpenART #2：新增独立分类脚本，只在 MCU 请求期间执行模型推理。

OpenART #2 优先在启动时同时加载卡通和数字模型：

```text
卡通：cartoon_V2.tflite（当前最新版，V1 保留回退）
数字：number_V1.tflite
```

两模型同时加载失败时，脚本明确报告模型内存错误。经过上板验证确认无法同时加载后，才退回按批次释放和切换模型的实现，不在首版中同时维护两套加载路径。

## 4. 科目二状态机

```text
S2_WAIT_MAP
-> S2_SCAN_BOX_PLAN
-> S2_SCAN_BOX_MOVE
-> S2_SCAN_BOX_CENTER
-> S2_SCAN_BOX_CLASSIFY
-> 扫完全部箱子
-> S2_SCAN_TARGET_PLAN
-> S2_SCAN_TARGET_MOVE
-> S2_SCAN_TARGET_CENTER
-> S2_SCAN_TARGET_CLASSIFY
-> S2_VALIDATE_BINDINGS
-> S2_SELECT_PUSH_TASK
-> S2_EXECUTE_PUSH
-> S2_CONFIRM_MAP
-> 下一任务或 S2_RETURN_HOME
-> DONE
```

`S2_WAIT_MAP` 只接受包含一个 `C`、数量相等且大于零的 `B/T` 地图。发车区画面和 `B=0,T=0` 不能触发求解或完成。

扫描阶段不推动箱子。若扫描期间 `B/T` 坐标集合意外变化，当前扫描结果失去可靠坐标基础，流程停车并报告地图变化错误。

## 5. 观察任务规划

### 5.1 候选观察格

每个待识别的箱子或目标只使用其上下左右四个相邻格作为候选观察格：

- `#`、`X`、`B` 不可作为观察格或导航通路。
- `T` 沿用当前求解器语义，可作为玩家通路。
- 候选格必须可由当前 `C` 通过小车导航 BFS 到达。
- 待识别对象必须是该候选格距离最近的同类型对象。
- 若存在另一个同类型对象与待识别对象等距，该候选格存在绑定歧义，必须排除。

### 5.2 动态最近邻顺序

对全部未识别对象及其合法候选格计算导航 BFS，选择动作数最少的任务。完成一次识别后，根据小车最新位置重新计算剩余任务，不使用固定行列顺序。

扫描顺序固定为：

1. 卡通模型识别全部箱子。
2. 数字模型识别全部随机目标。

### 5.3 到点流程

```text
到达观察格并停车
-> 向 OpenART #1 请求 3 帧小车精确中心
-> 校正 MCU pose 并确认当前观察位置
-> 向 OpenART #2 发送分类请求
-> 收到稳定分类结果
-> 绑定当前地图对象坐标与 class_id
```

每个观察点都先执行 OpenART #1 中心校正，避免多段扫描运动后的里程计误差把正确分类绑定到错误地图坐标。

### 5.4 超时与换位

单个候选观察格最多等待 20 秒获得稳定分类。超时后选择同一对象的下一个合法候选格。全部候选格均失败后停车并进入分类错误状态。

最坏情况下，一个对象可能在四个候选格累计等待 80 秒。这是已确认的容错优先策略。

## 6. 分类确认和绑定

### 6.1 类别语义

模型输出索引直接作为整数 `class_id`，范围为 `0..9`。标签中的 `00`、`01` 只是两位文本格式，MCU 不解析或保存英文标签。

```text
卡通模型 class_id N <-> 数字模型 class_id N
```

同一局中卡通类别和目标数字都不会重复。

### 6.2 三样本确认

OpenART #2 发送请求期间的每次推理结果，MCU 统一负责置信度门控和连续一致判断：

- 连续 3 个有效样本必须具有相同 `class_id`。
- 每个样本的置信度必须不低于 `750/1000`。
- 类别改变时清空连续计数，从新类别重新累计。
- 请求序号不匹配的迟到样本直接丢弃。

### 6.3 绑定表

MCU 按类别维护唯一坐标：

```c
box_by_class[10];
target_by_class[10];
```

同一批次识别到重复类别时不覆盖旧绑定，应更换观察格重新识别。全部对象识别完成后，箱子类别集合必须与目标数字集合完全一致；集合不一致时只重扫不匹配类别关联的对象。无法得到一致集合时停车，禁止猜测配对。

## 7. OpenART #2 UART 协议

### 7.1 硬件通道

```text
RT1064 UART4 TX C16 -> OpenART #2 RX
RT1064 UART4 RX C17 <- OpenART #2 TX
波特率 115200
```

UART4 由 OpenART #2 独占。当前 `LPUART4_IRQHandler()` 中遗留的相机和 GNSS 通用回调不得再读取 UART4 数据。

### 7.2 文本协议

```text
MCU -> ART2: VISION_MODE BOX
ART2 -> MCU: VISION_READY BOX

MCU -> ART2: VISION_REQ 17
ART2 -> MCU: VISION_SAMPLE 17 1 8 932
ART2 -> MCU: VISION_SAMPLE 17 2 8 947
ART2 -> MCU: VISION_SAMPLE 17 3 8 941
MCU -> ART2: VISION_ACK 17
```

字段定义：

- `request_id`：MCU 递增请求序号。
- `sample_id`：当前请求内 ART2 递增样本序号。
- `class_id`：分类整数 `0..9`。
- `confidence_q`：置信度千分值 `0..1000`。

数字目标阶段使用 `VISION_MODE TARGET`。两模型已加载时，该命令只切换当前模型引用并回复 `VISION_READY TARGET`。

OpenART #2 空闲时不进行推理，也不持续发送分类结果。收到匹配的 `VISION_ACK` 后停止当前请求；K4 急停时 MCU 可发送取消命令并忽略后续旧请求样本。

## 8. 指定配对求解

求解器增加指定箱子坐标和指定目标坐标的单任务接口。该接口复用现有单箱 BFS、动作编码和 waypoint 生成，不让求解器持有分类表。

科目二每轮对所有未完成绑定尝试指定求解：

1. 其他箱子保持不可通行。
2. 其他目标仍按当前地图通行语义处理。
3. 选择动作数最少的可解绑定任务。
4. 若当前绑定无解，继续尝试其他类别。
5. 全部剩余绑定都无解时才报告规划错误。

每次只向 executor 提交一个箱子任务。最后一个推箱 waypoint 保留 ART 地图确认语义，现有推箱前精确中心校正继续生效。

## 9. 箱子身份追踪和重规划

OpenART #1 只能识别黄色 `B`，不能识别其卡通类别，因此 MCU 必须在执行过程中维护身份。

- 每次只推动一个已知类别的箱子。
- 未选择箱子的坐标应保持不变。
- Push Retry 时比较执行前后的 `B` 坐标集合。
- 唯一消失的旧坐标和唯一新增的新坐标代表当前类别箱子的移动，更新该类别的 `box_cell`。
- 若箱子仍在原格，保留原坐标并重算。
- 若多个非当前箱子同时变化，身份无法可靠恢复，停车并进入 `E:Track`。

ART 稳定地图中 `B/T` 各减少 1 时，只有当前执行类别被标记完成。随后删除该类别绑定，并基于最新地图重新选择下一任务。

## 10. 状态显示和错误处理

复用 Execute 页现有状态行，不增加新页面和大批诊断字段：

```text
S2Map    等待科目二地图
BScan    扫描箱子
TScan    扫描目标
VPos     前往观察格
VCtr     OpenART #1 中心确认
VWait    等待 OpenART #2 分类
VRetry   更换观察格
Bind     校验绑定集合
S2Push   执行分类推箱
S2Ret    科目二返航
E:Class  分类或绑定集合失败
E:Track  箱子身份追踪失败
```

所有错误状态必须先停止底盘。K4 在扫描、分类、推箱和返航阶段均保持急停能力。

## 11. 配置项

首版只增加必要配置：

```c
#define COMPETITION_MODE_SUBJECT1_DEBUG      (1u)
#define COMPETITION_MODE_SUBJECT2_DEBUG      (2u)
#define COMPETITION_MODE_FULL                (3u)
#define COMPETITION_MODE                     (COMPETITION_MODE_SUBJECT2_DEBUG)
#define SUBJECT2_CLASS_CONFIDENCE_Q          (750u)
#define SUBJECT2_CLASS_STABLE_SAMPLES        (3u)
#define SUBJECT2_VIEW_TIMEOUT_MS             (20000u)
```

观察候选数量由四邻域自然限定，不增加独立配置。类别数量固定为模型的 10 类，不增加运行时扩展机制。

## 12. 验证要求

### 12.1 主机测试

- 随机箱子和随机目标的动态最近邻观察顺序。
- 墙、箱子阻挡、不可达候选和同类型等距歧义排除。
- UART4 请求序号、迟到样本、低置信度和连续三样本确认。
- 重复类别、箱子/目标集合不一致和针对性重扫。
- 指定箱子只能求解到指定目标。
- Push Retry 后唯一移动箱子的身份更新。
- 多箱异常变化触发身份错误。
- `SUBJECT1_DEBUG`、`SUBJECT2_DEBUG` 和 `FULL` 的科目切换。

### 12.2 OpenART 验证

- 两模型在 OpenART Plus 启动时同时加载成功。
- `VISION_MODE` 正确选择模型。
- 空闲时不推理，请求时持续输出样本，ACK 后停止。
- 卡通和数字模型输出索引与各自标签顺序一致。
- Python 语法检查通过。

### 12.3 上板验证

- 科目二调试模式可从发车区独立启动。
- 每个观察点先完成 ART1 中心校正，再绑定 ART2 类别。
- 多个对象同时出现在第一人称画面时不绑定错坐标。
- 随机目标位置可以全部扫描并建立唯一配对。
- 分类完成前不推动任何箱子。
- `FULL` 模式只按一次 K3，科目一返航后自动进入科目二。
- 科目一现有发车、推箱、重规划和返航行为不回归。
- Keil 编译为 `0 Error(s), 0 Warning(s)`。

## 13. 已选方案与未选方案

首版继续使用现有整图分类模型，通过选择唯一最近观察对象来完成坐标关联。暂不采用固定 ROI 多区域分类，也不重新训练多目标检测模型。若实测无法通过观察位置可靠隔离同类型对象，再单独评估检测模型，不在本次设计中提前引入。
