# 第三类致命错误锁存与人工恢复设计

## 目标

自动恢复已经没有可信依据，继续运动可能撞入虚拟墙、执行错误任务或失去底盘控制时，系统进入锁存停车状态。第三类错误不能由一次视觉丢帧或一次地图抖动直接触发；只有控制安全错误，或同一问题经过第一类降级和第二类同步恢复仍持续失败时，才能升级。

本设计与前两类错误处理组成完整分级：

```text
第一类：精确视觉缺失，粗状态可信
-> 直接降级继续

第二类：旧路径不可信，但新地图可能恢复
-> 短暂停车、同步、重规划

第三类：控制基础不存在，或连续恢复失败
-> 锁存停车，等待人工恢复
```

## 第三类来源

### 立即致命的控制错误

以下错误不经过第一、第二类恢复，第一次发生就必须停车：

- executor 输入为空、waypoint 数量非法或内部状态损坏。
- IMU 数据不可用，无法维持 yaw 闭环。
- 编码器、电机或底盘控制持续异常。
- 共享状态或临界区一致性遭到破坏。
- 用户按下 K4 急停。

这些情况下系统已经失去可靠运动基础，不能继续执行、重规划或自动返航。

### 视觉和地图持续不可恢复

以下问题经过两次第二类恢复仍然以同一原因失败时，第三次升级为第三类：

- ART1 持续没有完整合法地图。
- 地图持续没有 `C/+` 或同时存在多个 `C/+`。
- B/T 结构持续无法由途经目标、上位机完成或当前任务解释。
- 箱子或目标数量无原因增加。
- 精确中心和字符地图持续严重冲突。
- ART2 经过模式重发和重新请求后仍不返回 READY。
- 同一对象所有可达观察方向都无法得到有效分类。

### 任务逻辑确定不可执行

使用新地图并尝试所有允许的备选方案后仍失败时，升级为第三类：

- 所有同类 box-target 组合都不可解。
- 当前箱子的全部推箱路径被墙或其他箱子封死。
- 所有可达观察位置都已尝试。
- 类别数量经过局部重扫仍不一致。
- 对象类别无法根据剩余目标配额恢复。
- 返航允许的两个出口行都不可达。

## 同一错误的识别

恢复计数不能只按错误大类统计。以下信息共同组成恢复键：

```text
业务阶段
错误原因
当前对象或活动箱子
当前目标
当前观察方向或推箱方向（适用时）
```

例如“箱子 A 到目标 8 不可解”和“箱子 B 到目标 8 不可解”不是同一个错误，不能共用失败计数。

## 升级规则

同一恢复键的处理规则：

```text
第一次失败
-> 第一类降级或第二类同步

第二次相同失败
-> 换观察方向、同类箱子、目标或执行局部重扫

第三次完全相同失败
-> 进入第三类致命错误
```

以下任一事件表示恢复已经取得实际进展，必须清零对应恢复计数：

- 取得并接受一张合法新地图。
- executor 重新启动并完成一个 waypoint。
- B/T 等量减少。
- 成功分类一个新对象。
- 切换到新的箱子、目标或观察方向。

不能因为状态机重复进入同名状态就清零；必须有以上实际进展。

## 锁存停车动作

进入第三类时统一执行：

```text
stop_motion()
-> 取消当前 executor 路径
-> 取消 ART1 中心和观察请求
-> 取消 ART2 分类请求
-> 锁定当前 MCU yaw
-> 保留最后合法地图、home、分类结果和活动任务
-> 锁存具体错误原因和恢复键
-> 进入 FATAL_WAIT
```

第三类处理可以复用 `executor_set_error()` 完成最终安全停车，但不能调用会清除比赛上下文的完整重置流程。

锁存后主循环继续执行以下非运动工作：

- 解析 ART1/ART2 UART 数据。
- 刷新地图和错误状态显示。
- 扫描 K3/K4 按键。
- 保存最近错误原因、帧号和活动任务诊断信息。

锁存状态下不得自动恢复运动。

## 错误显示

第三类错误使用明确的 `F:*` 状态，不再把所有原因压缩成 `E:Ctr`、`E:S2C` 或 `E:?`：

```text
F:Drive   底盘、编码器或 IMU 不可用
F:ART1    ART1 持续没有合法地图
F:ART2    ART2 持续不响应
F:Map     地图结构持续非法
F:Plan    所有规划方案不可解
F:Class   分类集合持续不一致
F:Track   对象持续无法恢复
F:Return  返航不可完成
```

Execute 页继续保留当前 C 格、活动箱子、目标、最近业务状态和地图，方便现场判断失败位置。

当前 `screen.c` 缺少 `EXEC_ERROR_SUBJECT2_PLAN` 的文字映射，实施第三类显示时必须补齐，避免规划错误显示为 `E:?`。

## K3 人工恢复

第三类不要求重新上电。FATAL_WAIT 下按 K3 短按执行一次人工恢复：

```text
清除 fatal 锁存
-> 清除当前恢复计数
-> 保留 home、最后合法地图、分类结果和活动任务
-> 进入第二类 ART Sync 或 VSync
-> 等待一张新的合法地图
-> 重新规划后继续
```

K3 人工恢复不能直接恢复旧 waypoint，也不能使用触发致命错误的旧地图立即开动。

人工恢复后若再次出现相同致命错误，可重新锁存；不得形成自动的 FATAL_WAIT 与恢复循环。

## K4 急停

K4 保持最高优先级：

```text
立即停止电机
取消所有执行和视觉请求
退出本轮自动恢复
保持急停状态
```

K4 引起的第三类停车不能通过自动状态机解除，只能按现有人工操作重新开始。

## 自动返航边界

第三类发生后不默认自动返航。只有同时满足以下条件时，才允许人工恢复后重新尝试返航：

- 底盘、编码器和 IMU 正常。
- 存在一张新鲜合法地图。
- 地图中恰好一个 `C/+`。
- home 已记录且有效。
- 返航 BFS 可解。

出现 `F:Drive`、`F:ART1` 或 `F:Map` 时禁止自动返航，因为返航本身同样依赖底盘和地图。

任务未完成时也不能把“停车位置”错误标记为 `Done`。返航失败继续显示 `F:Return`，不得伪造完成结果。

## 与现有错误接口的关系

- `subject2_fail()` 只保留给最终升级后的第三类错误，不再处理第一、第二类临时问题。
- `executor_set_error()` 只用于控制安全错误和最终 fatal 锁存。
- `E:*` 继续表示可诊断的普通错误或恢复前状态；真正锁存统一显示 `F:*`。
- 第一、第二类恢复成功后不得遗留 `EXEC_STATE_ERROR`。

## 不变范围

- 不修改 BFS、20cm 格距、PID 和普通到点阈值。
- 不允许 fatal 状态自动沿旧路径继续。
- 不允许在地图或底盘不可信时盲目返航。
- 不清空已经确认的 home、分类结果和最后合法地图。
- 不把一次 ART 丢帧、一次中心超时或一次分类失败直接升级为第三类。

## 验收场景

- 一次中心丢帧不会进入 `FATAL_WAIT`。
- 一次地图结构异常会先进入第二类同步。
- 同一恢复键第三次完全相同失败时才锁存。
- 换箱子、目标或观察方向后不会继承旧恢复计数。
- B/T 等量减少或完成 waypoint 后恢复计数清零。
- 底盘或 IMU 控制基础丢失时第一次即进入 `F:Drive`。
- fatal 锁存时电机停止，但 UART、屏幕和按键仍工作。
- K3 从新地图同步开始恢复，不直接继续旧 waypoint。
- K4 急停不能被自动恢复解除。
- `EXEC_ERROR_SUBJECT2_PLAN` 不再显示为 `E:?`。
- `F:Drive/F:ART1/F:Map` 状态下不会自动返航。
