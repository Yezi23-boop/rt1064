# ART 第二类短暂停车同步恢复设计

## 目标

地图或对象状态出现冲突、旧路径已经不能安全继续时，停止当前 executor，获取停止之后的新 ART 地图并重新规划。恢复过程不能直接进入永久 `ERROR`；只有同一阶段、同一原因连续恢复失败时，才升级为第三类不可恢复错误。

本设计承接第一类可降级视觉错误：

- 精确视觉缺失但粗地图仍可信时，按第一类直接降级继续。
- 粗地图、对象位置或当前任务出现冲突时，按本设计短暂停车同步。
- 路径持续不可达、硬件错误或连续恢复失败时，交给第三类处理。

## 适用范围

第二类错误包括：

```text
ART 地图暂时缺失或结构非法
地图出现多个 C/+
精确中心与地图冲突且位置误差较大
小车已经不在当前路径预期格
箱子位置发生无法直接接受的变化
B/T 数量暂时不一致
科目二对象类别或身份暂时无法恢复
当前观察路径或推箱路径在新地图中不可解
精确车箱样本提供了与当前推箱方向冲突的可信证据
```

## 基本原则

第二类恢复允许短暂停车，但不调用 `subject2_fail()` 或 `executor_set_error()`。

停车只用于阻止旧路径继续运行：

```text
发现冲突
-> 停止并取消旧 executor 路径
-> 保留错误原因和当前 ART 帧号
-> 等待停止之后产生的新完整地图
-> 解释地图变化
-> 更新地图、pose、对象列表和任务基线
-> 重新规划并自动继续
```

恢复状态显示 `ART Sync`、`VSync`、`Replan`、`Rescan` 或 `Push Retry`，不得显示 `E:*`。

## 新地图要求

进入恢复状态时记录当前 `frame_count`。只处理 `frame_count` 之后发布的新完整地图，避免把触发错误的旧图再次作为恢复结果。

一张可用于恢复的地图必须满足：

- 完整通过 `MAP_BEGIN ... MAP_END` 原子发布。
- 字符集和地图尺寸合法。
- 恰好存在一个 `C/+`。
- B/T 变化能够由当前推箱任务、途经目标遮挡或上位机完成事件解释。

精确 `PLAYER_CENTER_GRID` 可以无效。中心无效时，恢复成功后的 executor 按第一类规则使用地图 C 格中心或 `offset=(0,0)`。

OpenART 当前已经使用 `STABLE_CHANGE_COUNT=3` 做逐格稳定滤波，且 ART1 实测约 3FPS。因此 MCU 恢复阶段不再固定要求两到三张相同地图；停止之后的第一张结构合法新图即可进入解释流程。

## 地图变化解释顺序

### B/T 等量减少

若箱子和目标数量同时减少相同数量：

```text
相信上位机已经完成一个或多个任务
-> 更新 B/T 确认基线
-> 更新科目二对象列表
-> 清除已经失效的活动箱子和目标限制
-> 使用最新地图重新规划
```

上位机完成事实优先于 MCU 旧路径和旧活动任务判断。

### 途经目标遮挡

若 ART 地图少一个 B、T 数量未减少，先检查是否满足现有途经目标归一化条件：

```text
最近完成动作是 U/D/L/R
规划动作重放得到的箱子位于 C 前方一格
该格在 ART 地图中为 T
该格不是当前任务最终目标
```

满足时把该格在 MCU 内部规范化为 `*`，同时计作一个箱子和一个目标，然后更新活动箱位置并重新规划。

不能解释为 `*` 时，不接受该图，继续等待下一张新地图。

### C 位置变化

若 B/T 结构正常，但地图 C 已不在当前路径预期格：

```text
取消旧路径
-> 使用新地图 C 作为新起点
-> 有配套精确中心时计算格内 offset
-> 无精确中心时 offset=(0,0)
-> 重新规划当前任务
```

不得继续执行基于旧 C 起点生成的剩余 waypoint。

### 对象位置或类别有歧义

科目二对象协调时：

- 能由原格、活动目标和剩余类别配额唯一恢复的对象继续保留。
- 已经完成或消失的目标从对象列表移除。
- 只有位置或类别无法唯一恢复的对象才标记为未识别。
- 只对未识别对象执行 ART2 局部重扫，不清空全部分类结果。

### 结构仍无法解释

出现以下情况时，本张地图不能作为恢复结果：

- B/T 数量不相等且无法规范化为 `*`。
- 箱子或目标数量无解释地增加。
- 同时出现多个 `C/+`。
- 箱子变化与最近推箱方向和上位机完成事件均无关。

继续等待下一张新地图，直到恢复时间耗尽。

## 科目一恢复入口

### 中心冲突

`E:Ctr` 若由中心和地图冲突、中心偏差异常或当前 C 已离开预期格引起，不再永久停车：

```text
停止旧 executor
-> 进入 ART Sync
-> 新地图合法后重新计算起点和 offset
-> solve_map()
-> 继续执行
```

### 车箱观察冲突

`OBSERVE_SAMPLE` 已提供可信证据，表明车或箱子不在当前推箱预期位置时：

```text
停止旧推箱链
-> 进入 ART Sync
-> 以新地图为准更新箱子位置
-> 重新规划
```

这与第一类“没有观察样本时使用格点路径继续”不同；已经取得冲突证据时不能忽略。

### 推箱准备动作失败

`BGap/BAlign/BNear/BRetry` 位置偏差过大或动作超时时，停止局部准备动作，使用新地图 C/B 重新规划，不直接进入 `E:BTim`。

### 现有完成和重试路径

- B/T 等量减少继续使用 `Host Sync`。
- B/T 没变化继续使用 `Push Retry`。
- 求解失败继续使用 `ART Retry`，但受本设计的恢复次数限制。

## 科目二恢复入口

### 中心或位置冲突

- `CRef`：进入 `VSync`。
- `CTim` 且任一轴剩余误差超过 2cm：进入 `VSync`。
- 精确中心显示 C 已离开当前观察格：进入 `VSync` 后重新选择观察路径。

### 地图和对象跟踪

- `Track`：进入 `VSync`，协调对象列表，必要时局部重扫。
- `ATim`：重置确认 tracker，继续等待新地图，不立即报错。
- 地图结构短暂非法：保持 `VSync`，等待下一张新图。

### 观察和规划

- `VPos` 找不到观察路径：用一张新地图重新计算一次。
- `Plan` 当前所有同类 box-target 组合不可解：新地图后重新枚举一次。
- `BSet` 类别数量仍不一致：只使数量异常类别失效并局部重扫。

### 推箱前车箱冲突

可信 `OBSERVE_SAMPLE` 显示小车不在正确推箱侧、箱子离开请求格或几何与推箱方向矛盾时，停止旧推箱任务并进入 `VSync`。新地图协调完成后重新选择具体 box-target 组合。

## 恢复次数和超时

每个业务阶段保存：

```text
recovery_reason
recovery_count
recovery_start_frame
recovery_start_ms
```

只累计“同一阶段、同一原因”的连续失败：

```text
第一次冲突
-> 新地图同步并重规划

第二次相同冲突
-> 换观察方向、换同类箱子、局部重扫或原目标重试

第三次仍是完全相同的冲突
-> 升级为第三类不可恢复错误
```

一旦恢复成功并重新进入正常执行，计数清零。

ART1 实测约 3FPS。单次第二类恢复总等待时间使用约 3 秒，理论上可覆盖约 9 个 ART1 处理周期。超过 3 秒仍没有任何合法完整地图时，继续等待通常无法提高恢复概率，应升级到第三类处理。

## 状态显示

第二类恢复复用 Execute 页现有 `S:`：

```text
ART Sync   科目一等待新地图
VSync      科目二等待新地图
Replan     使用最新地图重算
Rescan     科目二局部重扫
Push Retry 原目标推箱重试
```

恢复成功后立即切回 `Running`、`VPos`、`S2Push` 或返航状态。

## 不变范围

- 恢复期间不允许沿旧路径盲目继续运动。
- 不允许 MCU 修改 ART 发布地图中的 `C/+`、`B` 或 `T`。
- 不修改 BFS、20cm 格距、PID 和普通到点阈值。
- 不要求精确中心有效才能发布或接受结构合法地图。
- 不把真正的硬件错误或连续三次相同恢复失败无限重试。

## 验收场景

- 中心与地图冲突后停止旧路径，新地图合法时自动重规划继续。
- B/T 等量减少时立即接受上位机结果并更新基线。
- 少一个 B 且满足途经目标条件时规范化为 `*`。
- B/T 暂时无法解释时不发布错误快照，下一张恢复后继续。
- 地图 C 改变时旧 waypoint 不再继续执行。
- 科目二 `Track` 冲突只重扫有歧义对象。
- `VPos/Plan` 首次不可解时先用新地图重试，不立即永久错误。
- 同原因第一次、第二次恢复不会进入 `EXEC_STATE_ERROR`。
- 同阶段第三次完全相同冲突才升级第三类。
- 恢复成功后对应计数清零。
