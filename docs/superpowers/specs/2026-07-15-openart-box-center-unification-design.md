# OpenART 请求式箱子中心统一设计

## 背景

字符地图中的 `B` 表示虚拟推箱系统认可的箱子格，负责 BFS、任务选择和推箱结果确认。黄色箱子精确中心表示当前画面中箱子的连续几何位置，负责推箱前的小车对齐和安全靠近。两者不能混为同一个状态来源。

当前 OpenART 已有全图箱子中心检测、指定格箱子中心选择和调试绘制，MCU 已有 `OBSERVE_REQ`、三帧中值和二维安全准备位。需要统一的是正式识别入口、坐标换算、请求关联和配套地图校验，而不是把地图中多个真实 `B` 合并成一个。

## 方案选择

考虑过三种方案：

1. 每帧精确识别所有箱子并重写地图 `B`。信息最丰富，但计算量高，而且箱子动画跨格时会提前改变虚拟格点状态，不采用。
2. 只在 `OBSERVE_REQ row,col` 时精确识别指定箱子。粗 `B` 负责规划，精确中心负责推箱准备，性能和职责最清晰，采用。
3. MCU 直接把请求 `B` 格中心当作箱子中心。实现简单，但无法修正箱子偏格和半边车身推箱问题，不采用。

## 目标

- 字符地图中的 `B` 继续由稳定格点识别和上位机虚拟状态决定。
- 精确箱子中心只在推箱链准备阶段按请求识别，不修改、移动或增删字符地图中的 `B`。
- 科目一和科目二共用同一个 OpenART 箱子中心入口、UART请求协议、MCU样本过滤和 executor 准备位状态机。
- 小车中心和箱子中心来自同一画面，并与一张新的唯一 C 规范地图配套。
- 三帧样本全部属于当前一个 `OBSERVE_REQ`，新请求不得复用旧箱子中心。
- 识别失败不发送空坐标，也不使用上一只箱子的中心。

## 非目标

- 不用精确箱子中心判断箱子是否完成一格移动。
- 不用精确箱子中心判断 B/T 是否消失或触发重规划。
- 不在推箱过程中持续运行视觉闭环。
- 不识别或保存目标点精确中心。
- 不修改 BFS、waypoint、PID、格距或现有二维准备位运动顺序。

## 职责边界

```text
稳定字符地图 B
  -> 箱子数量和所在格
  -> BFS 与单箱任务选择
  -> 推箱后 B/T 变化确认

OBSERVE_REQ 指定箱子中心
  -> 推箱前车箱几何关系
  -> SAFE_GAP / ALIGN_PERP / APPROACH
  -> 不修改字符地图 B
```

即使精确箱子中心越过了请求格边界，也只能用于准备位计算。只有后续稳定字符地图确认 `B` 移动或 B/T 减少，业务层才能更新箱子格状态。

## OpenART 统一入口

正式请求和调试绘制共用一个指定箱子解析入口，例如：

```text
resolve_requested_box_center(image, grid_points, request_row, request_col)
  -> pixel_x, pixel_y
  -> col_q, row_q
```

该入口复用当前黄色 blob、跨格 blob 切分和中心去重算法，但只返回与请求格匹配的一个中心：

1. 请求 row/col 必须位于 16x12 地图范围内。
2. 当前稳定规范地图的请求格必须为 `B`。
3. 只在请求格附近建立 ROI，不把全图调试中心直接交给正式推箱流程。
4. 候选中心按到请求格中心的距离选择最近项。
5. 候选中心行列偏差分别不得超过请求格中心的 `0.8` 格。
6. 多个候选距离完全相同时视为不确定，本帧不返回样本。
7. 没有匹配中心时返回无结果，不复用历史箱子中心。

当前 `player_center_to_grid_q()` 实际同时服务小车和箱子，应改为语义中立的坐标换算入口，例如 `image_center_to_grid_q()`；小车和箱子禁止各自维护另一套透视逆变换。

## 请求与样本

请求格式保持：

```text
MCU -> OBSERVE_REQ box_row,box_col
```

OpenART 收到新请求后：

1. 清除上一请求的样本计数和箱子中心临时结果。
2. 使用唯一 C 设计中的统一小车中心解析入口识别小车中心。
3. 使用本设计的指定箱子入口识别请求箱子中心。
4. 只有同一画面中两个中心都有效时才形成一个样本。
5. 先发送由该小车中心生成的唯一 C 规范地图，再发送观察样本：

```text
MAP_BEGIN
<12 行规范地图>
PLAYER_CENTER_GRID car_col_q,car_row_q 1
MAP_END
OBSERVE_SAMPLE index,car_col_q,car_row_q,box_col_q,box_row_q
```

6. 连续发送 3 个新样本后结束当前请求。

OpenART 发送的是3个原始新观测，不在 OpenART 内部先做中值再重复发送同一个结果。

## MCU 接收校验

MCU 对每个 `OBSERVE_SAMPLE` 执行统一校验：

- 当前存在一个活动的 `OBSERVE_REQ`。
- `index` 必须按 `1,2,3` 顺序到达。
- 样本前必须收到一张新的、合法的唯一 C 规范地图。
- 样本小车中心必须与该地图的 `PLAYER_CENTER_GRID` 完全一致。
- 该配套地图的请求 row/col 必须仍是 `B`。
- 小车和箱子中心必须位于 16x12 范围内。
- 箱子中心相对请求格中心的行、列偏差分别不得超过 `0.8` 格。

任一条件不满足时丢弃该样本，不推进样本计数。新 `OBSERVE_REQ` 到来时清除 UART观察队列、executor三帧缓存和预取有效标志。

## 三帧融合与使用

MCU executor 是三帧融合的唯一所有者：

```text
car_col_q 三帧中值
car_row_q 三帧中值
box_col_q 三帧中值
box_row_q 三帧中值
```

科目一 `art_replan` 和科目二 `subject2` 只负责发起请求、轮询样本和处理超时，不再各自计算另一套箱子中心。两者都把合法样本交给 `executor_apply_art_box_observation()`，并由同一个 `executor_start_pre_push_box_preparation()` 生成准备位。

融合后的箱子中心只用于：

```text
SAFE_GAP    沿推箱轴退到安全距离
ALIGN_PERP  沿垂直轴对齐箱子中心
APPROACH    沿推箱轴靠近到一格距离
```

不使用融合结果修改 `map_source_struct`、solver箱子格、B/T基线或任务绑定。

## 参数语义

OpenART 的请求格候选范围和 MCU 的 `ART_BOX_MATCH_MAX_OFFSET_Q` 统一表达同一规则：

```text
abs(box_col_q - requested_col_center_q) <= 80
abs(box_row_q - requested_row_center_q) <= 80
```

其中 `80` 表示 `0.8` 格。Python 与 C 无法共享同一个编译期宏，但必须使用同名语义、相同数值并由协议测试锁定。

观察样本数固定为3。它与小车 `CENTER_REQ` 的5帧中值用途不同，不要求合并成同一个数量。

## 失败处理

- OpenART 未找到小车或指定箱子中心：本帧不发送 `OBSERVE_SAMPLE`。
- 3帧未在等待时间内收满：沿用现有 `BObs` 重试流程。
- 新请求开始：上一请求未消费的样本和预取结果全部失效。
- 样本几何校验失败：丢弃本次视觉准备结果，按照当前已确认策略释放等待并继续原 waypoint，不触发 `BGeo` 硬停车。
- 二维准备位运动超时：保留现有 `BTim` 停车错误，避免带着不确定位置继续推箱。
- 识别失败和几何失败均不得使用上一只箱子的中心作为兜底。

## 性能

- 普通周期地图不运行箱子精确中心检测。
- 只有活动的 `OBSERVE_REQ` 或明确开启箱子中心调试时才运行黄色 blob 中心算法。
- 正式请求只处理指定格附近 ROI；全图所有箱子中心检测只用于调试，不参与正式控制。
- 每个请求额外发送3张配套规范地图，数据量有限，换取样本与小车格的明确配对。

## 验证

OpenART 测试至少覆盖：

- 指定格只有一个箱子时返回正确中心。
- 相邻箱子同时存在时选择距离请求格最近的箱子。
- 跨格箱子中心允许在请求格中心 ±0.8 格范围内返回。
- 超过 ±0.8 格、请求格不是 B、无黄色中心和候选距离相同时不发送样本。
- 新请求不复用旧箱子中心和旧样本序号。
- 调试全图检测和正式指定格检测共用同一中心解析逻辑。
- 小车与箱子中心来自同一帧，每个观察样本前发送配套规范地图。
- 小车和箱子共用同一图像到网格坐标换算。

MCU 测试至少覆盖：

- 只有新规范地图配套、序号连续、中心一致且请求格仍为 B 的样本才进入队列。
- 三帧中值结果正确，科目一和科目二进入同一个 executor 准备位接口。
- 箱子中心在 ±0.8 格边界内接受，越界拒绝。
- 新请求清除旧UART队列、预取状态和executor样本。
- 几何失败释放原 waypoint，不进入 `E:BGeo`。
- `BObs` 重试和 `BTim` 停车策略保持有效。
- 精确箱子中心不会修改字符地图 B、B/T 基线或solver状态。

完成前运行 OpenART Python 测试、UART观察协议测试、executor/科目一/科目二主机测试、Python语法检查和Keil编译，要求固件达到 `0 Error(s), 0 Warning(s)`。

## 假设

- 推箱前小车已经停车，观察3帧期间虚拟箱子不会主动移动。
- 上位机稳定字符地图中的请求格 `B` 是本次任务要推的箱子。
- 相邻箱子中心之间通常接近一格，最近请求格中心的候选能够区分目标箱子。
- 箱子完成、移动和消失仍以稳定字符地图及B/T变化为最终事实。
