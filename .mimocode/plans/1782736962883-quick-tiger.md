# ART 错误重试 + ART 即时真理 改动计划

日期：2026-06-30

## 核心原则

**ART 地图永远是真值。** 不停车、不报错，所有异常都重试获取 ART 地图并重新求解。

## 改动范围

**只改 `art_replan.c`**，约 5 处。

## 改动详情

### 1. 超时：重启等待，不报错

**文件**：`art_replan.c:354-365`

**当前**：超时 → `art_replan_cancel()` + `executor_set_error()` → 停车

**改为**：超时 → `art_replan_begin()` 重新进入同一阶段 → 不停车

```c
if((time_ms() - art_wait_start_ms) >= EXEC_ART_SYNC_TIMEOUT_MS)
{
    // ART 超时不停车，重启等待继续获取最新地图
    art_replan_begin(art_replan_phase, update);
    if(0 != update)
    {
        update->run_state = "ART Retry";
        update->redraw = 1;
    }
    return;
}
```

### 2. 无效帧：静默丢弃，不升级错误码

**文件**：`art_replan.c:207-222`

**当前**：`art_stats_valid_for_solve()` 返回 0 → 设置 `art_timeout_error = EXEC_ERROR_ART_SYNC` + 重启稳定性

**改为**：去掉错误码升级，只重启稳定性继续等

```c
if(0 == art_stats_valid_for_solve(&stats))
{
    art_replan_restart_stability();
    if(0 != update)
    {
        update->run_state = "ART Retry";
        update->redraw = 1;
    }
    return;
}
```

### 3. 求解失败：重启等待，不报错

**文件**：`art_replan.c:272-289`

**当前**：`solve_map()` 返回 0 → 设置 `art_timeout_error = EXEC_ERROR_ART_PLAN` + 显示 "Plan Fail"

**改为**：去掉错误码，重启等待

```c
else
{
    *context->elapsed_ms = time_ms() - start_ms;
    art_replan_wait_fresh_frame();
    if(0 != update)
    {
        update->run_state = "ART Retry";
        update->redraw = 1;
    }
}
```

### 4. 移除 art_timeout_error 变量

**文件**：`art_replan.c:27`

`art_timeout_error` 不再需要，删除变量和所有赋值处。

### 5. INITIAL 阶段的 art_stats_done 保留

`art_stats_done()`（箱子+目标消失 → 任务完成）保留不变，因为这是正确的完成状态。

## 改动后的行为

| 场景 | 当前行为 | 改后行为 |
|------|----------|----------|
| ART 超时 3s | 停车 ERROR | 重启等待，不停车 |
| 无效帧（C!=1 或 B!=T） | 升级错误码，超时后停车 | 静默丢弃，继续等 |
| 求解失败 | 超时后停车 ERROR | 重启等待，不停车 |
| ART 显示车已到位但 MCU 没到 | 视为到位，重解算续跑 | 同左（ART 即时真理） |
| 任务完成（B/T 消失） | DONE | DONE（不变） |
| K4 短按/长按 | 停车 | 停车（不变） |

## 验证

1. Run 页选 ART 来源，K3 发车
2. 正常执行：每段末等 ART → 校正 pose → 重解算 → 续跑
3. 遮挡摄像头模拟 ART 丢失：车不停车，继续等 ART 恢复
4. ART 显示箱子已推完但 MCU 没推：车信任 ART，继续执行
5. K4 短按：正常停车
